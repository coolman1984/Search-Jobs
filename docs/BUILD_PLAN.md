# خطة البناء (بعد موافقتك على نقطة التوقف)

## الاختيارات التقنية
- **Python 3.11+ من غير مكتبات خارجية** (مكتبة بايثون القياسية بس: sqlite3 وurllib وtomllib وemail). أقل حاجات تتكسر، وأسهل في المراجعة.
- **SQLite** للبيانات، و**ملفات نصية** (Markdown وTOML وJSON) لكل حاجة إنت ممكن تقراها أو تعدلها: معايير التقييم، والمصادر، وبطاقات الفرص، والمسودات.
- **وكيل Claude** في المهام المجدولة على السحابة: بيشغّل المحرك، وبيستخدم الموصلات الرسمية (Indeed وGmail وGitHub)، وبيعمل البحث والكتابة.

## إزاي البيانات بتمشي

```
جامعين (APIs وRSS)  ─┐
موصل Indeed (الوكيل) ─┼─▶ inbox/*.json ─▶ توحيد + إزالة تكرار ─▶ opportunities.db
تنبيهات البريد (الوكيل)─┘                                   │
                                                         ▼
                     التقييم من 100 (scoring.toml) + جملة تشرح الدرجة
                                                         │ أعلى 3–5
                                                         ▼
                     الإثراء (مين هم، حجمهم، حضورهم الرقمي، اللي ناقصهم، قناة تواصل عامة)
                                                         ▼
                     باحث الحلول (GitHub والويب: مكتبات، رخصة، نضج، ربط بمشاريعك)
                                                         ▼
                     بطاقة الفرصة + مسودة العرض (عربي أو إنجليزي)
                                                         ▼
                     تقرير اليوم = تذكرة GitHub (الإشعار يوصل موبايلك)
                                                         ▼
                     ⛔ بوابة الموافقة (في الكود) ⛔
                                                         ▼
                     مسودة في Gmail (مش إرسال)، أو نص جاهز + رابط للمنصة الحمرا
                                                         ▼
                     متابعة: أُرسلت ← رد ← اجتماع ← عرض سعر ← تعاقد/رفض  +  تعلّم أسبوعي
```

## بوابة الموافقة — إزاي مستحيل الوكيل يوافق بدالك
1. كل مسودة ليها **بصمة** (SHA-256 لنصها بالظبط).
2. في تقرير الصبح، جنب كل فرصة، هيبقى فيه **لينك موافقة**. اللينك ده بيفتح صفحة GitHub وفيها ملف `approvals/<الفرصة>.approve` مكتوب فيه البصمة. إنت **بتدوس Commit**، وخلاص.
3. GitHub بيوقّع أي حفظ بيتعمل من الموقع **بمفتاحه الخاص** (web-flow). والكود بيقبل الموافقة بس لو:
   - التوقيع ده سليم (الفحص بيحصل بالمفتاح العام بتاع GitHub)،
   - والكاتب هو حسابك إنت،
   - والبصمة مطابقة للمسودة الحالية حرف بحرف.
4. الوكيل المجدول **مايقدرش يزوّر توقيع GitHub**، فحتى لو حاول يكتب ملف موافقة بنفسه، الكود هيرفضه. وده هيتثبت باختبار.
5. فوق ده: إعدادات المشروع (`.claude/settings.json`) **بتمنع** أدوات الإرسال في Gmail (send وreply وforward) على مستوى البرنامج نفسه، مش بالتعليمات بس. إنشاء المسودة بس هو المسموح.

## القرارات الآمنة اللي هاخدها لوحدي لو ماردّتش (هتتوثق في DEVELOPMENT_HISTORY.md)
- لو المستودع لسه عام: **مفيش أسماء أشخاص ولا بيانات تواصل ولا مسودات بتتحفظ في git**، والتقرير هيبقى ملخص من غير أسماء.
- لو مافيش نطاقات مسموحة على الشبكة: نشتغل بالموصلات بس (Indeed وGmail والبحث).
- الحد اليومي للتواصل المباشر: **2 رسالة**، ومفيش أي متابعة آلية.
- أي فرصة فيها اسم جهة عملك أو منافسيها أو مورّديها: **تترفض تلقائيًا**.
